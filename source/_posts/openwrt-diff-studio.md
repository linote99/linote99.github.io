# OpenWrt Diff Studio：在手机上给 OpenWrt 做差异更新

给 E5、MU300 这类设备装上 OpenWrt 以后，新版发行包隔一段时间就会出一版。想升级的话，最省事的办法是重新完整安装一遍，但这样配置要重配，自己装的插件要重装，等于从头来过。

电脑版的 OpenWrt Diff Studio 解决的就是这个问题：比较新旧两版完整包，只把变了的文件做成一个差异包，再推到设备上更新，其余东西原样保留。问题是它需要一台电脑，而设备旁边往往只有手机。

所以我把它移植到了安卓上。手机上就能生成差异包，也能直接连上设备完成更新。导出的格式和电脑版完全相同，两边生成的包可以互相使用。

## 两件事：做补丁、打补丁

App 分成两页，各管一件事。

| 页面 | 做什么 | 结果 |
|---|---|---|
| 生成差异包 | 选旧版和新版两个完整发行 ZIP，分析变更 | 导出完整更新包 ZIP，或只导出 `.ota` |
| 更新设备（OpenWrt Updater） | 导入 `.ota`，用 SSH 连上设备 | 检查通过后应用更新，可自动重启 |

**生成差异包**时，App 会分析三类东西：根文件系统里变化的文件、内核与启动镜像、软件包依赖。E5 的发行包里根文件系统是 ext4 镜像，MU300 / F50 / V50 / U30 Air 的是 tar 包，两种都能读。

导出时有两个选择：

- **完整更新包 ZIP**：里面有 `update.ota`、电脑端更新器和说明，拿到电脑上也能用
- **仅 `.ota` 文件**：只给手机端的「更新设备」用，体积更小

**更新设备**这一页，填设备地址和 root 密码，点「连接并检查」，全部检查通过后再点「确认应用此补丁」。

## 更新时什么会保留

差异更新的意义在于「只换该换的」。设备端的更新程序对下面这些东西是明确不动的：

- 板载固件、NV、vendor 等设备专属内容（`lib/firmware`、`opt/e5/nv`、`opt/mu300/firmware` 这类路径）
- 首次启动脚本 `etc/uci-defaults` 和更新器自己的状态目录
- 软件包管理器的数据库不会被整个覆盖，而是**逐个软件包合并**

最后一条最关键。你自己装的插件，新版基础镜像里没有它，它的文件和数据库记录都会保留；就算新版恰好把这个插件收成了默认组件，也保留你装的那个版本和它的全部文件，不会出现「文件是旧的、数据库记录是新的」这种对不上的情况。

账户文件也是按行合并：已有的用户不动，只追加新版里新增的。所以更新后 root 密码还是你改过的那个。

还有一个设计我觉得挺对：如果你手动改过某个系统文件（比如临时打了个补丁），更新程序**不会因此拒绝整个更新**，而是把你改过的那份原样备份下来，再换成新版。

## 一次更新是怎么跑完的

点下「连接并检查」到更新完成，中间大致是这样：

1. **先送一套独立的运行环境上去。** 把补丁里带的 BusyBox 和启动脚本传到设备的 `/tmp/unisoc-ota-<随机串>`，逐个核对 SHA-256，再确认需要的命令都齐全。之后的操作都用这套环境，不依赖设备上原有的工具版本。
2. **检查空间并上传补丁。** 先看 `/etc` 剩余空间够不够（补丁大小再加 32 MiB 余量），然后把 `.ota` 传上去，校验通过后才改成正式文件名。
3. **核对版本。** 设备的机型系列、配置和当前版本，必须和补丁的「旧版」完全一致。如果设备已经是新版了，会直接提示你是不是把新旧两个包选反了。
4. **确认后应用。** 检查和应用是两次独立的连接。应用前会比对设备的 SSH 主机密钥指纹，和检查时那台对不上就拒绝——防止中途 Wi-Fi 切到了另一台设备。
5. **设备端独立执行。** 更新事务在设备上自己跑，App 只负责看进度。这时候关掉 App、手机锁屏都不影响设备写入。
6. **重启。** 勾了自动重启的话，事务完成后才会发重启；设备还在写入或回滚时，App 会拒绝重启请求。

写入前，设备端会把要替换的文件和启动镜像都备份好；写的过程中每个文件都回读校验。如果中途出错，会按备份恢复，App 里能看到回滚结果。

## 移植时遇到的几个问题

### 连上设备 Wi-Fi，流量却走了流量卡

更新路由器的时候，手机连的往往是设备自己的 Wi-Fi，而这个 Wi-Fi 常常还没有互联网。安卓遇到「无互联网」的 Wi-Fi 时，会把默认网络留给移动数据，结果 App 去连 `192.168.9.1` 的请求被发到了蜂窝网络上，自然连不通。

解决办法是不用默认网络：连接前遍历手机上所有网络，看哪个网络的路由表能到达设备地址，选前缀最长（最精确）的那条，然后把 SSH 连接绑定到这个网络上。VPN 一律跳过。这样不管是 Wi-Fi、USB 网络共享还是以太网，都能自动找对路。

### 旧版 Dropbear 的加密算法

一些设备固件里的 Dropbear 比较老，只支持 `diffie-hellman-group14-sha1`、`aes128-cbc`、`hmac-sha1` 这些现在默认被禁用的算法。电脑版用的 paramiko 会保留这些兼容选项，安卓这边的 JSch 默认不会，所以我手动把它们加回了候选列表，现代算法仍然优先。

### 手机上没法挂载 ext4 镜像

电脑版读 E5 发行包里的 ext4 根文件系统，用的是 dissect.extfs 这个库，直接解析镜像，不需要挂载。安卓上普通 App 既不能挂载，也跑不了这个 Python 库。

我按 dissect.extfs 的行为用 Java 重写了 ext4 读取部分，目标是让手机生成的补丁和电脑生成的**逐字节一致**。也正因为这部分是参照 AGPL 项目实现的，APK 整体按 AGPL-3.0 分发。

这一步要先把镜像解到手机的临时目录里，所以分析 E5 发行包时，手机至少要留出几百 MB 空间。

### 保存对话框把文件名改成了 `.bin`

有些手机的系统保存对话框不认识 `.ota` 这种扩展名，会把文件名截短，再按 MIME 类型换成 `.bin`，导出的文件就成了一个看不出是什么的 `xxx-.bin`。

现在导出后会检查实际保存的文件名，被改了就自动改回完整的名字和 `.zip` / `.ota` 扩展名，同名文件自动加序号；实在改不了，会提示你手动改扩展名。

### 长任务不能被系统杀掉

分析一个几百 MB 的发行包、上传补丁，都要花一段时间。这期间 App 会切到前台服务并保持唤醒，避免切到后台被系统回收。设备端的写入本来就独立运行，所以就算 App 真被杀了，重新打开后点「读取设备状态」就能接上。

### 设备端文件不能动一个字节

设备端的运行时文件（更新引擎、启动镜像处理、RPC 接口等）直接沿用电脑版，每个都有 SHA-256 指纹。仓库里用 `.gitattributes` 禁止了对它们做换行符转换——在 Windows 上 clone 一下就把 LF 变成 CRLF 的话，导出的更新包会校验失败。

## 使用步骤

1. **生成差异包**：在「生成差异包」页分别选旧版（设备当前运行的版本）和新版完整 ZIP，点「分析差异」，确认结果后点「导出差异包」或「仅导出 .ota 文件」。
2. **连上设备**：手机连设备的 Wi-Fi，或者用 USB 网络共享。
3. **更新设备**：在「更新设备」页选 `.ota`，填设备地址和 root 密码，点「连接并检查」；全部通过后点「确认应用此补丁」。

也可以在文件管理器里直接用本 App 打开 `.ota` 或 `.zip`。

## 使用须知

- **只导入可信来源的补丁**：补丁会以 root 权限写入系统文件。
- **旧版必须和设备当前版本一致**，否则检查这一步就会拒绝。
- **更新期间不要断电，也不要手动重启设备。**
- 设备需要用完整安装器装过一次，有完整的版本信息，差异更新才能识别它。

## 适用范围

- 手机：Android 8.0 或更高版本。
- 设备：E5（ext4 根文件系统）和 MU300 / F50 / V50 / U30 Air（tar 根文件系统）的 OpenWrt 完整发行包；新旧两个包必须属于同一机型系列和配置。
- 网络：手机和设备在同一网络（连设备 Wi-Fi 或 USB 网络共享），并且知道设备的 root 密码。默认管理地址 E5 是 `192.168.9.1`，MU300 是 `192.168.77.1`，也可以填 `地址:端口`。

第一次给设备装 OpenWrt，可以用另一个工具：[OpenWrt 安装器（安卓版）](/posts/openwrt-android-installer/)。
